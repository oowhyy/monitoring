## 🎨 Особенности реализации

### 1. Infrastructure as Code

Всё настроено через конфиги - не требуется ручная настройка в UI:
- Datasource Loki автоматически добавлен в Grafana
- Дашборд автоматически импортирован
- Можно версионировать в Git

### 2. Параметризация

Все пути, порты и настройки через `.env`:
```bash
GRAFANA_PORT=3000
LOKI_PORT=3100
LOG_SOURCE_PATH=./logs
```

Изменили `.env` → перезапустили → всё работает с новыми настройками

### 3. Готовый дашборд

Предустановленный дашборд включает:
- График логов по уровням
- Статистика (ошибки, предупреждения, info)
- Поток всех логов
- Панель только с ошибками
- Фильтры по job и level

### 4. Производственный подход

- Правильные названия полей в JSON логах
- RFC3339Nano timestamp
- Structured logging
- Retention policies
- Компакция данных
- Кэширование запросов

### 5. Удобство разработки

**Makefile команды:**
```bash
make help        # Помощь
make setup       # Первоначальная настройка
make start       # Запуск
make stop        # Остановка
make restart     # Перезапуск
make logs        # Просмотр логов
make status      # Статус сервисов
make test-logs   # Создать тестовые логи
make clean       # Очистить данные
make update      # Обновить образы
make backup      # Создать backup
make check       # Проверить конфигурацию
```

**Bash скрипты:**
- `scripts/check-system.sh` - полная проверка работоспособности системы

## 🔧 Конфигурация

### Основные параметры (.env)

```bash
# Порты
GRAFANA_PORT=3000          # Веб-интерфейс Grafana
LOKI_PORT=3100             # API Loki

# Пути к данным
LOKI_DATA_PATH=./data/loki
GRAFANA_DATA_PATH=./data/grafana
LOG_SOURCE_PATH=./logs     # Откуда брать логи

# Аутентификация
GRAFANA_ADMIN_USER=admin
GRAFANA_ADMIN_PASSWORD=admin  # Измените в продакшене!
```

### Настройка retention (loki.yml)

```yaml
# Хранить логи 30 дней (по умолчанию)
retention_period: 720h

# Изменить на 7 дней:
retention_period: 168h
```

### Добавление новых источников логов

**1. В docker-compose.yml:**
```yaml
promtail:
  volumes:
    - ./logs:/var/log/app:ro
    - /var/log/nginx:/var/log/nginx:ro  # Добавить новый источник
```

**2. В promtail.yml:**
```yaml
scrape_configs:
  - job_name: nginx
    static_configs:
      - targets: [localhost]
        labels:
          job: nginx
          __path__: /var/log/nginx/*.log
```

## 🔍 Поиск и фильтрация

### Примеры запросов

**Все логи приложения:**
```logql
{job="go-application"}
```

**Только ошибки:**
```logql
{job="go-application", level="error"}
```

**Поиск по тексту:**
```logql
{job="go-application"} |= "database connection"
```

**Подсчет ошибок за 5 минут:**
```logql
sum(count_over_time({job="go-application", level="error"} [5m]))
```

**Топ-10 самых частых ошибок:**
```logql
topk(10, sum by (error) (count_over_time({job="go-application", level="error"}[1h])))
```

Больше примеров в `LOGQL_EXAMPLES.md`

### Для локальной разработки

- Локальной разработки
- Тестирования
- Обучения
- Демонстрации

### Для продакшена

⚠️ Перед использованием в продакшене необходимо:

1. **Безопасность:**
   - Изменить пароли
   - Настроить HTTPS/TLS
   - Включить аутентификацию в Loki
   - Настроить RBAC в Grafana

2. **Надежность:**
   - Использовать внешнюю БД для Grafana (PostgreSQL)
   - Настроить backup данных
   - Настроить кластер Loki для HA
   - Мониторить саму систему мониторинга

3. **Производительность:**
   - Выделить достаточно ресурсов
   - Настроить retention policy
   - Использовать SSD для хранения
   - Настроить limits в Loki

См. раздел "Production Deployment" в README.md
